# 记忆工坊照片与长廊相框联动设计

## 目标

让记忆工坊中的每个记忆节点和长廊中的一个相框建立一一对应关系：用户上传照片后，照片立即出现在下一个空相框；用户为该节点选择 GLB 后，点击相框照片即可打开对应的 3D 模型预览。

## 已确认的范围

- 产品仍是当前的本地 Demo，不接外部生图、分离或 Rodin API。
- 3D 模型绑定方式为：新增照片时同时选择对应 GLB。
- 照片上传成功后立即显示在长廊相框中，不等待后续阶段完成。
- 模型选择或生成完成后更新同一个相框，不新增第二个相框。
- 现有四张静态记忆和它们已经绑定的 GLB 保持不变。
- 新增节点先占用现有空相框；没有空位时给出提示，不自动改变走廊结构。
- 图片和 GLB 先保存在当前浏览器会话中。刷新后的持久化留给后续服务器接入阶段。

## 用户流程

1. 用户进入记忆工坊，点击“新增记忆”，填写年份和标题。
2. 用户上传照片。上传成功后，工坊显示照片预览，长廊下一个空相框同步出现这张照片。
3. 用户在“3D 化”阶段选择对应的 GLB 文件。GLB 只绑定到当前节点，不影响其他节点。
4. 用户可以继续检查主体、背景、卡通化和组合结果。
5. 用户点击相框中的照片，打开现有 3D 查看器：标题、年份和地点来自当前节点，模型来自该节点绑定的 GLB。
6. 用户替换同一节点的照片时，原相框位置不变，只更新照片纹理；替换 GLB 时，点击相框打开新模型。
7. 用户点击“保存到时间轴”后，节点状态变为“已加入长廊”，但不会再次创建相框。

## 数据结构

### 记忆节点

在现有工坊节点字段上增加以下运行时字段：

```js
{
  id: "memory-2026-1760000000000",
  year: "2026",
  title: "这一年的故事",
  previewUrl: "blob:...",       // 当前浏览器会话中的照片 URL
  originalName: "photo.jpg",
  glbUrl: "blob:...",           // 当前浏览器会话中的 GLB URL，可为空
  glbName: "memory.glb",
  galleryFrameIndex: 2           // 绑定的相框槽位，可为空
}
```

`previewUrl` 和 `glbUrl` 只作为当前会话的运行时资源，不写入 localStorage。保存的节点元数据中保留文件名和 `galleryFrameIndex`，避免刷新后误认为已有可加载资源。

### 相框槽位

长廊初始化时为每个相框登记一个槽位引用：

```js
{
  group,
  side,
  z,
  photoWidth,
  photoHeight,
  photoMesh: null,
  nodeId: null
}
```

静态四张照片也通过同一套槽位挂载逻辑创建。新增节点只寻找 `nodeId === null` 的槽位，挂载后记录 `galleryFrameIndex` 和 `nodeId`。

## 场景更新方式

- `buildEmptyGalleryFrames()` 负责建立木框、空白背板和槽位引用。
- `applyFramePhoto(slot, asset)` 负责创建或更新照片平面、加载纹理、设置裁剪和点击数据。
- `mountStudioMemory(node)` 负责为节点分配槽位并调用 `applyFramePhoto`。
- 照片替换时复用原槽位和原照片平面，释放旧纹理和旧 Blob URL，避免重复相框和内存泄漏。
- `state.photoMeshes` 始终包含当前可点击的照片平面；点击逻辑继续复用现有 `openMemory3D()`。
- 传给查看器的资产对象使用 `glbUrl`，没有 GLB 时保留照片并显示现有“模型待加入”状态。

## 工坊交互

- 上传区域继续选择图片。
- “3D 化”阶段增加 GLB 文件选择控件，限制 `.glb`，显示文件名和“已绑定/未绑定”状态。
- 选择新 GLB 后只更新当前节点的 `glbUrl`、`glbName`，不触发新的相框分配。
- 若没有空相框，上传仍保留在工坊节点中，但状态栏提示“长廊相框已满，请先扩展展位”；用户不会误以为照片已展示。
- 点击已挂载照片后，3D 查看器标题和模型状态必须对应当前节点；缺少 GLB 时仍可关闭查看器返回长廊。

## 错误处理

- 非图片文件：拒绝上传并提示支持 PNG/JPG/WEBP。
- 非 GLB 文件：拒绝绑定并提示“请选择 .glb 模型”。
- GLB 加载失败：保留照片相框，查看器显示“模型待加入 · 已保留照片预览”。
- 相框已满：节点仍保存在工坊，显示明确提示，不覆盖现有照片。
- 节点被重复上传或切换：通过 `galleryFrameIndex` 和 `nodeId` 复用原槽位，禁止重复生成相框。
- 页面刷新：恢复节点元数据和相框占用标记，但由于文件 Blob 未持久化，照片/模型显示为待重新选择；不伪装成已加载资源。

## 测试与验收

新增自动检查覆盖：

- 相框槽位登记和空槽分配存在。
- 新节点上传后调用挂载逻辑。
- 照片平面写入节点资产并加入 `state.photoMeshes`。
- GLB 选择控件只接受 `.glb`，并把 URL 绑定到当前节点。
- 同一节点替换照片或 GLB 不增加相框数量。
- 现有静态四张照片的路径和 GLB 映射不变。

浏览器验收流程：

1. 新增一个年份节点并上传一张图片。
2. 返回长廊，确认下一个空相框出现该照片。
3. 回到工坊为同一节点选择 GLB。
4. 点击相框照片，确认查看器标题、年份和 GLB 对应。
5. 替换图片并再次点击，确认仍使用同一相框位置。
6. 上传超过空位数量的照片，确认显示容量提示且已有照片不被覆盖。

## 后续扩展

后续接服务器或 API 时，只替换资源保存层：将 `previewUrl`、`glbUrl` 换成服务器地址，并保留节点 ID、槽位 ID和查看器接口不变。IndexedDB 持久化也可以在不改变长廊挂载接口的情况下加入。
